An optimizer for problems with a known computation graph.

Free. Fully local — no server, no license key, no network call, the same as torch.optim.Adam. If you can write down your objective exactly, SoftOpt uses it to correct your optimizer's trajectory on every step.

Where it doesn't help

Two honest limits, stated plainly rather than discovered the hard way:

  • A moving target. Full reinforcement learning — or anything with a continuously shifting policy, adversary, or distribution — is outside SoftOpt's validated scope. The correction needs a fixed objective to compute against.
  • A landscape with unpredictable curvature. The correction assumes the curvature along a random direction is consistently one-signed — true across the physics, circuit and engineering problems tested here. Where it isn't, the correction stops helping.

Quick start

# write your model in plain Python, nothing special
from softopt import SoftOpt, soft_compile

def my_model(theta):
    x, y = theta
    return (x - 2.0)**2 + np.exp(y) * x

g_delta = soft_compile(my_model, n_params=2)
opt = SoftOpt(2, g_delta, lr=0.02)

for step in range(num_steps):
    grad_estimate = my_gradient_estimate(theta)
    theta = opt.step(theta, grad_estimate)

soft_compile traces your model once and derives the exact directional derivative from it — no approximation, and no derivative code to write. It works with arithmetic, powers, abs, sqrt, exp, log, sin, cos, tanh, loops, and branching, in plain Python or numpy. It then verifies the result against your own model before returning it.

The math, precisely

The full soft-number algebra is available from the package (from softopt import SoftNumber, sadd, smul, ...), each operation cited to an exact page and formula in Foundations of Soft Logic (Klein & Maimon, Springer 2024):

SoftNumber wraps these with operator syntax (x + y, x * y, x ** 3, x.sqrt()) and is verified, axiom by axiom, against the book's own proofs that bridge numbers form an abelian group under addition and a ring under both operations.

Every derivative SoftOpt uses is produced by propagating these operations through your model. There is no second path and no approximation step.
